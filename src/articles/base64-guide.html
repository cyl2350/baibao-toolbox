打开网页源码,经常能看到一长串以 = 结尾的字符,这就是 Base64。它是什么?有什么用?为什么中文会乱码?一文说清。

一、Base64 是什么?

Base64 是一种用 64 个可打印字符表示二进制数据的编码方式。它把 3 个字节(24 位)转成 4 个字符(每个 6 位),所以编码后体积约为原来的 4/3。那 64 个字符是:A~Z、a~z、0~9、+、/,末尾用 = 补齐。

它的本质不是加密,而是「翻译」——把二进制翻译成文本,方便在只能传输文本的通道里传递。

二、Base64 的常见用途

  • 邮件附件:SMTP 协议主要传输文本,附件先 Base64 编码再发送;
  • 图片内嵌:CSS 或 HTML 里用 data:image/png;base64,xxxx 直接内嵌小图标,减少 HTTP 请求;
  • 接口鉴权:HTTP Basic Auth 的用户名密码就是 Base64 编码的;
  • 传输二进制:JSON 里不能直接放二进制,先转成 Base64 字符串;
  • 加密前的预处理:部分签名算法先把数据转成 Base64 再处理。

三、为什么中文 Base64 会乱码?

Base64 编码的是「字节」而不是「字符」。中文在 UTF-8 下占 3 个字节,如果工具按单字节字符(如 Latin-1)逐字编码,得到的结果在另一端就无法还原成中文。正确做法是:编码前把字符串转成 UTF-8 字节序列,解码后按 UTF-8 还原。

所以,跨平台传递 Base64 时,一定要确认两端都按 UTF-8 处理,否则中文必乱。

四、常见问题

Base64 是加密吗?

不是。Base64 是可逆的公开编码,任何拿到字符串的人都能解码。涉及敏感信息必须使用真正的加密算法。

为什么有的 Base64 末尾有 = ,有的没有?

= 是填充符,当数据长度不是 3 的倍数时补齐。有些实现会省略填充,解码时也能自动处理。

URL 里的 Base64 为什么会有 - 和 _?

标准 Base64 的 + 和 / 在 URL 里有特殊含义,所以 URL 安全版本把它们替换为 - 和 _(Base64URL)。

Base64 和 Hex(十六进制)有什么区别?

都是二进制转文本的编码。Hex 用 16 个字符、体积翻倍;Base64 用 64 个字符、体积 4/3。Base64 更省空间,Hex 更易读。

总结:Base64 = 二进制的「文本翻译官」,不是加密。处理中文记住 UTF-8,传 URL 用 URL 安全版,敏感数据请加密。
